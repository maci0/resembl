# Resembl Go service candidate

This package is an experimental portable HTTP boundary for one preconfigured Resembl index. It does not replace the embedded Python API, CLI or local `resembl serve`. It is not a deployable public service: an application must provide an `Authorizer` that authenticates the caller and checks the exact configured resource and `query` verb against current native authority. Missing authority is rejected at construction. No Casdoor authorization-review endpoint is assumed to exist.

`POST /v1/find` accepts the existing `/find` JSON body (maximum 8 MiB), requires a nonempty query, and forwards it through the `Engine` port after authorization. Concurrency and request timeout are configured at construction. `GET /healthz` is local process liveness and performs no dependency I/O. Unavailable authority or engine fails closed. Results must be treated as sensitive corpus data; responses are not cacheable.

`NewLocalEngine` is an optional adapter to a separately started `resembl serve` on loopback. The host must isolate that unauthenticated backend, pin and verify its engine version, configuration and index identity, and provision its resource limits. The adapter refuses redirects and bounds response size. The portable handler itself does not launch processes and can use a different qualified backend on VM, container, Kubernetes or serverless environments. A caller timeout does not prove that the Python engine stopped computing. The VM/container command requires a private, pre-created persistent custody directory. It atomically reserves a slot before dispatch and leaves it occupied after an uncertain backend outcome, including across process restart. All replicas sharing an engine must share the same persistent directory and capacity setting. This single-host filesystem adapter is not a distributed or serverless custody owner; it does not verify physical stop or automatically release orphaned claims. A qualified operator must establish that the exact engine execution stopped before repairing any slot. Do not use this as a durable cancellable job or for mutations.

The candidate also forwards `/v1/find-batch` with the existing engine batch semantics. `cmd/resembl-service` and its container entry point default to deny-all authorization. For a private single-index service, `-token-file` can enable an operator-managed bearer credential for the configured resource. Generate 32 random bytes and encode them as 64 lowercase hex characters; place the value in a private regular file readable only by the service. It is read once at startup: restart the service to rotate or revoke it. This grants all holders query access to that index and is not a native tenant identity, per-user authorization, or audit trail. Use a trusted authenticated TLS proxy and network controls when clients cross a host boundary; never pass the secret in command-line arguments. Supply `-custody` pointing to the private persistent directory; startup fails without it. The local engine and its index must be provisioned separately. This slice does not yet expose index mutation, durable jobs, real Casdoor integration or version/index attestation. Those need an owner-backed protocol, native authorization and compatibility qualification before public rollout. The existing Python interfaces remain unchanged.

Run `go test -race ./...` here. To exercise the real local engine, start a disposable `resembl serve` and set `RESEMBL_TEST_ENGINE_URL` to its loopback URL for `go test -run TestActualWarmEngine`.

The experimental `PinnedSQLiteEngine` calls `/find-pinned` on a compatible warm engine. That endpoint takes a canonical SHA-256 over the actual SQLite snippet, LSH and metadata rows while holding a SQLite writer fence, checks the supplied digest, and performs the query under the same fence. It rejects a stale index rather than rebuilding it under the proof, and limits the identity scan to one million rows and 64 MiB of encoded data. It does not support non-SQLite databases or batch requests. The pinned protocol also requires a trusted runtime-manifest digest and the warm process generation from `/runtime-generation`. Before and after the query, the backend checks its executable and every currently loaded module file against the owner-provided manifest. The VM command requires all three pins and remains deny-all. This is file integrity under an immutable, trusted supervisor and filesystem, not remote or hardware attestation: the owner must qualify manifest construction before startup, dependencies loaded later, native libraries and binary identity. It is not a production activation.
